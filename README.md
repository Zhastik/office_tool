# PDFwork

Веб-приложение для локальной обработки PDF, изображений, видео и аудио. Файлы и результаты остаются на устройстве пользователя.

## Запуск через Docker Compose

Нужен Docker Engine с Linux-контейнерами и Docker Compose v2. В Windows можно использовать Docker Desktop.

~~~sh
docker compose up --build -d --wait
docker compose ps
~~~

Интерфейс доступен на [localhost:8765](http://localhost:8765/). Настройки интерфейса, порта и версии можно переопределить через переменные среды или файл `.env` по образцу `.env.example`.

~~~sh
docker compose logs -f web api
docker compose down
~~~

Для обновления соберите образы повторно той же командой `docker compose up --build -d --wait`. При развёртывании на отдельной машине подключите HTTPS к единой точке входа `web`. HTTPS или localhost требуются для прямой записи больших файлов на диск в поддерживаемом браузере.

## Архитектура

~~~mermaid
flowchart LR
  Browser["Браузер · Web Workers"] -->|"GET / HEAD"| Web["web · Nginx"]
  Web -->|"/api/* · внутренняя сеть"| Api["api · FastAPI"]
~~~

| Компонент | Ответственность |
|---|---|
| **Браузер** | Проверяет исходники и выполняет обработку. Сохраняет результат через локальный `blob:` URL или файловый дескриптор браузера. |
| **web** | Раздаёт React-сборку, воркеры, WASM и модели OCR. Выставляет CSP, MIME-типы и правила кеширования. Передаёт `/api/*` во внутреннюю сеть Docker. |
| **api** | Предоставляет служебный HTTP-контракт и запускается в собственном контейнере без опубликованного порта. |

Границы проходят по ответственности и развёртыванию. У браузерных операций общее локальное состояние текущей вкладки. Nginx обращается к API по HTTP. Каждый экземпляр FastAPI обрабатывает запросы независимо, поэтому его можно заменить без переноса данных. Compose проверяет готовность API перед запуском веб-сервиса. При сбое API уже запущенный Nginx продолжает раздавать интерфейс и локальные обработчики.

Оба контейнера работают непривилегированно с файловой системой только для чтения. Nginx и FastAPI принимают GET и HEAD без тела запроса. CSP этих двух режимов берётся из одного файла `server/browser-headers.json`. Журналы доступа содержат идентификатор запроса, статус и время обработки. По `X-Request-ID` можно сопоставить запись шлюза с записью API.

| Endpoint | Назначение |
|---|---|
| `GET /healthz` | Nginx отвечает и принимает запросы. |
| `GET /api/health` | FastAPI запущен, режим обработки — `browser`. |
| `GET /api/ready` | Проверка готовности FastAPI через шлюз. |
| `GET /api/v1/info` | Имя сервиса, версия и режим обработки. |

## Разработка без Docker

Фронтенду нужен Node.js 22.12+, серверу — Python 3.10+. На Windows окружение, сборку и FastAPI можно подготовить из PowerShell.

~~~powershell
npm.cmd ci
npm.cmd run build
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --require-hashes -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn server.main:app --host 127.0.0.1 --port 8765 --no-access-log
~~~

FastAPI в локальном режиме раздаёт и API, и собранный интерфейс. Для работы над React с горячей перезагрузкой используйте `npm.cmd run dev`. Сборка берёт модели OCR и ресурсы PDF.js из зафиксированных npm-зависимостей. Dockerfile закрепляют базовые образы по digest. После изменения `requirements.in` обновите lock-файл через `uv`.

~~~sh
uv --no-python-downloads pip compile --python-version 3.10 --universal --generate-hashes --default-index https://pypi.org/simple --output-file requirements.txt requirements.in
~~~

## Операции и пределы

| Категория | Операции | Пределы MVP |
|---|---|---|
| PDF | Объединение, разделение по диапазонам, извлечение, удаление, перестановка и поворот страниц, извлечение текстового слоя, OCR сканов в TXT. | До 150 МиБ суммарно и до 20 000 страниц в редактируемом документе. Защищённые PDF требуют открытой копии, PDF с полями форм или подписи можно прочитать, операции со страницами требуют статичной копии. OCR обрабатывает до 25 выбранных страниц за задачу. |
| Изображения | Конвертация статичных JPEG, PNG и WebP, изменение размеров, сжатие JPEG/WebP, OCR в TXT. | До 128 МиБ, 40 Мп и 16 384 пикселей по стороне. Конвертация перекодирует растр, для JPEG прозрачность заменяется белым фоном. |
| Видео | Обрезка в MP4 с копированием дорожек, сжатие в MP4 (H.264) или WebM (VP8) с выбором разрешения и битрейта. | Одна видеодорожка и до одной аудиодорожки. Обрезка зависит от ключевых кадров и совместимости кодеков с MP4. Кодирование зависит от конфигураций WebCodecs. |
| Аудио | Конвертация и обрезка, вывод в WAV или Ogg Opus. | Одна аудиодорожка, декодирование зависит от исходного формата. При необходимости больших WAV автоматически используется RF64. |

По умолчанию небольшой результат скачивается из браузера. Предел этого пути для медиа — 128 МиБ на результат. Крупные исходники читаются частями. Для крупных результатов используется поэтапная запись на диск. Объём свободного пространства, формат дорожек и возможности браузера ограничивают обработку. Тесты на реальных роликах 5–20 ГБ и разных устройствах нужны для публикации гарантированных размеров.

## Дополнительные инструменты

Каталог содержит 43 инструмента с поиском по названиям и форматам. Панель «Допустимые настройки» показывает диапазоны, примеры ввода и ограничения выбранной операции.

| Группа | Возможности |
|---|---|
| Документы | PDF → DOCX/HTML, PDF → JPG, DOCX → PDF/JPG, PPTX → PDF, HTML → PDF, текст → PDF/DOCX/PNG, изображения → PDF. |
| Таблицы | PDF → XLSX/CSV, CSV → XLSX, XLSX → CSV/JPG/PDF, перенос таблиц из DOCX, OCR изображения в XLSX, экспорт операций из банковской выписки. |
| Изображения и OCR | Инверсия цветов, OCR одного изображения или пакета, изображение → DOCX, перевод надписей на фото. |
| Коды | Генерация QR в PNG, чтение QR и распространённых линейных штрихкодов по фотографии. |

Экспорт DOCX, HTML и PPTX в PDF переносит текстовое содержимое в единый шаблон. PPTX сохраняет порядок слайдов. Преобразование PDF в DOCX, HTML, XLSX и CSV использует текстовый слой. Столбцы PDF и фотографий восстанавливаются приблизительно. CSV импортируется в UTF-8 и сохраняет исходные текстовые значения, включая начальные нули. Выписки поддерживают структуру «Дата», «Описание», «Сумма». Строки, которые не удалось однозначно разобрать, сохраняются отдельно.

Перевод надписей выполняется через встроенный локальный Translator API поддерживаемого настольного Chrome или Edge. Доступны направления русский → английский и английский → русский. Для первого запуска браузеру может понадобиться скачать языковой пакет.

## Как устроена обработка

- `src/App.tsx` и `src/Settings.tsx` — выбор операции и файлов, параметры, прогресс, отмена и сохранение.
- `src/domain.ts` — каталог, форматы, лимиты и протокол обмена с воркером.
- `src/processor.worker.ts` — отдельный воркер на проверку файла или выполнение операции. Движки загружаются по требованию.
- `src/engines/pdf.ts` редактирует страницы через pdf-lib. `pdf-reader.ts` отдаёт PDF.js диапазоны байтов из локального файла, рендерит по одной странице для OCR. `image.ts` проверяет размеры до декодирования и работает через OffscreenCanvas. `ocr.ts` загружает модели с адреса приложения и передаёт в Tesseract только локальные данные через воркер.
- `src/engines/media.ts` читает диапазоны локального файла через Mediabunny, копирует пакеты или использует WebCodecs. Для записи на диск используются ограниченные буферы и обратное давление. Крупный MP4 сохраняется как fMP4. Результат фиксируется после завершения записи. При штатной отмене временная запись прерывается. Браузер может оставить пустой файл, созданный диалогом выбора места.
- `server/main.py` обслуживает только GET и HEAD. CSP разрешает скрипты и модели с адреса приложения. Приложение не содержит загрузчика файлов, аналитики или серверного хранилища.

## Проверка

~~~powershell
npm.cmd run check
npm.cmd run build
npm.cmd run check:deployment
npm.cmd run smoke
npm.cmd run smoke:tools
~~~

HTTP-проверка покрывает CSP, MIME, кеширование, передачу служебных запросов и отклонение запросов с телом. Smoke-тесту нужны запущенный стек или локальный FastAPI, установленный Google Chrome и `ffmpeg`/`ffprobe` в PATH. Можно задать `PDFWORK_URL` и `PDFWORK_BROWSER_EXECUTABLE`. Тест создаёт синтетические документы и медиа и проверяет скачанные результаты независимыми инструментами. Путь прямой записи проверяется с файловым дескриптором OPFS. Сетевая проверка допускает только запросы ресурсов приложения с того же адреса. Если языковой пакет отсутствует в тестовом профиле, проверка перевода подменяет Translator API и проверяет передачу распознанного текста и сохранение результата.

GitHub Actions на push и pull request собирает оба контейнера и запускает проверки через Nginx. В Linux CI видео перекодируется в WebM для воспроизводимости на хостах с разной поддержкой профилей AVC.

Дополнительный прогон многогигабайтного MP4 включается переменной PDFWORK_LARGE_MEDIA=1. Он генерирует видео размером около 5 ГиБ и пишет почти весь результат на диск. Для прогона нужно около 12 ГиБ свободного места.

На Windows сквозной прогон прошёл в Chrome и Edge. В Chrome синтетический H.264 MP4 размером 5 403 109 490 байт сохранился после обрезки как файл fMP4 размером 5 393 709 070 байт за 33,8 с через дескриптор OPFS. Повторная операция с отменой сохранила предыдущий результат. Это один прогон для обрезки без перекодирования.
